# 검수일정 관리 — 사용 설명서

외주업체가 신청한 검수 일정을 **등록 → 일정 협의 → 확정·변경·취소 → 검수 → 합격/불합격**까지 관리하고,
단계마다 업체에 메일로 알리는 Windows 프로그램입니다.
데이터는 부서가 함께 쓰는 **클라우드독 동기화 폴더**에 파일로 저장합니다 (DB 없음).

## 1. 설치

### 설치파일 받기
1. GitHub 저장소 → **Actions** → 왼쪽 **Windows 설치파일** → 오른쪽 **Run workflow** 를 누릅니다.
2. 10~15분 뒤 실행이 초록색(✓)으로 끝나면, 그 실행을 눌러 맨 아래 **Artifacts** 의 `installer` 를 내려받습니다.
3. 압축을 풀면 `InspectionScheduler-Setup-1.0.0.exe` 가 있습니다.

> 이 작업은 GitHub의 실제 Windows PC에서 **설치파일을 만들고 → 조용히 설치하고 → 실행해서 엑셀 가져오기까지 자동 시험**합니다.
> 시험 화면은 같은 곳의 `smoke-screenshots` 에서 볼 수 있습니다.

### 설치하기
1. `InspectionScheduler-Setup-1.0.0.exe` 를 실행합니다.
2. **"Windows의 PC 보호" 파란 창**이 뜨면 → **추가 정보** → **실행**.
   (회사 코드서명 인증서로 서명하지 않아서 뜨는 안내입니다. 인증서가 있으면 없앨 수 있습니다.)
3. 설치 대상은 **나만(현재 사용자)** 를 고르면 관리자 권한 없이 설치됩니다.
4. 설치가 끝나면 바탕화면과 시작 메뉴에 **검수일정 관리** 아이콘이 생깁니다.

- 설치 위치(기본): `C:\Users\<사용자>\AppData\Local\Programs\InspectionScheduler`
- 지울 때: Windows 설정 → 앱 → **검수일정 관리** → 제거. (동기화 폴더의 데이터는 지워지지 않습니다.)
- 새 버전 설치: 새 설치파일을 그냥 실행하면 덮어 설치됩니다. 데이터·설정은 그대로입니다.

## 2. 처음 실행 — 데이터 폴더 정하기

처음 실행하면 **데이터 폴더를 선택하세요** 화면이 나옵니다.

| 상황 | 고를 것 |
|---|---|
| 부서에서 **처음** 쓰는 사람 (한 명만) | **새 데이터 폴더 만들기** → 클라우드독 동기화 폴더 안에 빈 폴더(예: `검수일정`)를 골라 시작 |
| 나머지 부서원 | **이미 쓰고 있는 데이터 폴더에 연결** → 같은 폴더 선택 (검수 건수·마지막 저장자가 보이면 맞는 폴더) |

- **표시 이름**: 변경 이력·협의 기록에 작성자로 남는 이름입니다 (예: 홍길동).
- 폴더 위치는 **이 PC에만** 기억합니다. 나중에 설정 → 데이터 폴더에서 바꿀 수 있습니다.
- 바탕화면·내 문서처럼 공유되지 않는 폴더를 고르면 다른 사람이 볼 수 없으니 주의하세요.

## 3. 하루 업무 흐름

```
① 업체에 빈 양식 보내기 ─▶ ② 업체 회신 엑셀 가져오기 (신청번호 부여)
        ▼
③ 일정 협의 (협의 기록) ─▶ ④ 확정 (검수자 배정 필수) ─▶ ⑤ 업체에 확정 회신 메일
        ▼                                     ▲
   (변경되면 '변경됨' → 다시 확정 ─────────────┘)
        ▼
⑥ 검수 ─▶ ⑦ 결과 입력 (합격/불합격) ─▶ ⑧ 업체에 결과 통보 메일
```

1. **빈 양식 보내기**: 엑셀 가져오기 화면 또는 설정 → 엑셀 양식의 **[빈 양식 내려받기]** → 파일을 업체에 메일로 보냅니다.
2. **회신 엑셀 가져오기**: 업체가 보낸 파일을 **엑셀 가져오기** 화면에 끌어다 놓습니다 → 행별로 확인 → **[N건 가져오기]**.
   신규 건에는 `IN-2026-0001` 형식의 신청번호가 붙습니다.
3. **일정 협의**: 상세 화면 **[협의 시작]**, 통화·메일 내용은 **일정 협의** 탭에 기록합니다.
4. **확정**: 상세 화면 **[확정]** → 검수일·시간·장소·**검수자**를 넣습니다. 충돌 조건에 걸리면 경고가 뜹니다.
5. **확정 회신 메일**: **[메일 보내기]** → 미리보기에서 확인 → 발송.
   **같은 업체에 같은 날 확정한 건은 한 통으로 묶여** 신청번호·일정 목록이 들어갑니다.
6. **결과 입력**: 검수 후 상세 화면 **[결과 입력]** → 합격/불합격(불합격은 사유 필수) → **[저장 후 결과 메일 미리보기]** → 발송.

> 업체에 가는 메일은 **반드시 미리보기를 거쳐** 사람이 확인하고 보냅니다. 자동으로 바로 나가지 않습니다.

## 4. 화면별 사용법

### 대시보드 (첫 화면)
- **요약 카드**: 오늘 검수 / 이번 주 검수 / 충돌 경고 날짜 / 처리 필요
- **상태별 건수**: 칩을 누르면 그 상태로 걸러진 목록이 열립니다.
- **처리 필요**: 등록 후 협의 전 · 협의 지연(3일 이상) · 결과 미입력 · 메일 미발송. 줄 끝 링크로 바로 처리합니다.
- **다가오는 검수**: 7일 안의 확정 일정 (D-Day / D-1 / D-2…).

### 달력
- **월/주** 보기, [이전]/[다음]/[오늘], 업체·검수자·상태 필터.
- 색은 상태입니다 (회색 등록, 노랑 협의중, 파랑 확정, 보라 변경됨, 연빨강 취소, 초록 합격, 빨강 불합격).
- **노란 칸 + "충돌 n건"** 은 충돌 조건을 넘는 날입니다. 일정을 누르면 상세, 날짜를 누르면 그날 목록.

### 목록
- 검색, 기간·업체·검수자·상태·결과 필터, 머리글을 눌러 정렬.
- 여러 건 체크 → **검수자 배정 / 상태 변경(협의중·확정·취소)** 을 한 번에. 안 되는 건은 건너뛰고 이유를 알려줍니다.
- **[엑셀 내보내기]**: 지금 보이는 목록(필터·정렬 그대로)을 엑셀로 저장합니다.
- 검수일 칸의 **"충돌"**, 결과 칸의 **"결과 미입력"** 표시를 확인하세요.

### 검수 건 상세
| 탭 | 내용 |
|---|---|
| 기본정보 | 업체가 처음 신청한 값과 현재 값 비교 (바뀐 칸 노랑). [기본정보 수정] |
| 일정 협의 | 협의 내용 기록 |
| 검수 결과 | 합격/불합격, 실제 검수일, 검수자, 불합격 사유, 메모 + 첨부파일 |
| 첨부파일 | 회의록·검수자료·성적서 등 (끌어다 놓기). 열기/삭제 |
| 메일 이력 | 보낸 메일(성공/실패/수동 기록)과 본문 |
| 변경 이력 | 누가 · 언제 · 무엇을 · 이전값 → 새 값 · 사유 |

- 강조된(남색) 버튼이 **지금 해야 할 일**입니다.
- 첨부를 삭제해도 파일은 `첨부/<신청번호>/_삭제됨/` 에 보관됩니다.

### 엑셀 가져오기
- 여러 파일을 한 번에 넣을 수 있습니다. 행마다 **신규 / 수정 / 오류** 로 판정합니다.
- **노란 칸 = 경고, 빨간 칸 = 오류**. 칸에 마우스를 올리면 이유가 보입니다.
  (필수값 누락, 날짜·시간·수량·이메일 형식, 없는 신청번호, 과거 날짜, 목록에 없는 품목, 충돌 조건 등)
- 오류 행은 기본으로 빠지지만, 직접 체크하면 확인 창을 거쳐 가져올 수 있습니다.
- 신청번호가 적힌 행은 **수정본**으로 보고 바뀐 칸만 `기존값 → 새값` 으로 보여줍니다.
  (아직 확정 전이면 검수 일정도 따라 바뀌고, 확정된 건은 신청 내용만 바뀝니다.)
- 원본 파일은 `원본/YYYY-MM/` 에 보관됩니다.

### 메일 미리보기
- 받는 사람·참조·제목·본문·첨부를 확인·수정한 뒤 **[발송]** (자동) 또는 **복사 → 웹메일 → [발송 완료로 기록]** (수동).

### 업체 관리 / 검수자 관리
- 업체: 담당자·이메일·연락처, 업체별 검수 이력, **[일정 확인서]** (기간을 골라 업체별 일정표 엑셀 생성).
  가져오기 때 엑셀의 담당자·이메일이 자동 반영됩니다.
- 검수자: 이름·부서·이메일·**Windows 계정**·사용 여부. '사용 안 함'은 배정 목록에서 빠집니다.

### 설정
| 탭 | 내용 |
|---|---|
| 충돌 조건 | 규칙별 켜기/끄기·기준값, 검수 불가일, 강제 진행 허용 |
| 메일 템플릿 | 등록·확정(회신)·변경·취소·합격·불합격·검수자 알림 문구와 치환값 |
| 메일 발송 설정 | 자동(SMTP)/수동, 서버·포트·보안, 이 PC의 메일 계정·비밀번호, 테스트 메일 |
| 알림 | 며칠 전, 팝업, 알림 메일, 미리보기 |
| 엑셀 양식 | 검수 품목 목록, 빈 양식 내려받기 |
| 데이터 폴더 | 폴더 위치, 백업 보관 개수, '편집 중' 유효 시간, **백업에서 복원** |
| 사용자 | Windows 계정 ↔ 표시 이름 |

## 5. 여러 명이 함께 쓸 때

- **편집 중 표시**: 누가 고치기 시작하면 다른 PC 화면 위에 **"○○○ 편집 중"** 이 뜹니다 (30분 넘게 갱신이 없으면 무시).
- **덮어쓰기 방지**: 내가 불러온 뒤 다른 사람이 먼저 저장했으면 저장하지 않고
  **"○○○이(가) HH:MM에 수정했습니다. 새로 불러온 뒤 다시 작업하세요."** 가 뜹니다 → **[새로 불러오기]** 후 다시 입력.
- 같은 순간에 둘이 저장해도 한 명만 저장되고 다른 한 명은 위 안내를 받습니다 (조용히 사라지지 않음).
- 오래 열어 둔 화면은 가끔 **[새로 불러오기]** 를 눌러 최신 내용을 보세요.
- 클라우드독이 동기화 중일 때 아주 짧은 순간 겹치면 클라우드독이 "충돌 사본" 파일을 만들 수 있습니다. 그런 파일이 보이면 관리자에게 알려 주세요.

## 6. 메일 설정 (사내 IT 확인 필요)

기본은 **수동** 방식입니다 (프로그램이 받는 사람·제목·본문을 만들어 주면 웹메일에 붙여넣어 보냄).

### 자동(SMTP)으로 쓰려면 사내 IT에 확인할 것
- [ ] 회사 웹메일에서 **SMTP 발송이 허용**되는지 (계정별 설정이 필요한지)
- [ ] **SMTP 서버 주소**
- [ ] **포트와 보안 방식** — 보통 `587 + STARTTLS` 또는 `465 + SSL/TLS`
- [ ] 회사 네트워크(방화벽)에서 그 포트로 나갈 수 있는지

### 설정 순서
1. 설정 → **메일 발송 설정** → **자동 SMTP** 선택, 서버·포트·보안 방식 입력 (모든 PC 공통).
2. **메일 계정·비밀번호는 각자 PC에서** 입력합니다. 각자 자기 계정으로 보냅니다.
   비밀번호는 Windows 계정으로 암호화해 **그 PC에만** 저장되고, 공유 폴더·기록에는 남지 않습니다.
3. **[설정 저장]** → **[테스트 메일 보내기]** 로 본인에게 시험 메일이 오는지 확인.

## 7. 검수자 알림

우리 쪽 검수자에게만 보내며, 업체에는 가지 않습니다. (설정 → 알림)

- **팝업**: 프로그램을 켤 때와 켜 둔 채 날짜가 바뀔 때, **이 PC 사용자에게 배정된** 다가오는 검수를 보여줍니다.
  → 검수자 관리에서 그 사람의 **Windows 계정**을 적어 두어야 합니다 (비우면 표시 이름이 같을 때 연결).
- **알림 메일**: 그날 **처음 프로그램을 연 PC** 가 검수자 모두에게 한 번 보냅니다. 다른 PC는 다시 보내지 않습니다.
  자동(SMTP) 방식이고 그 PC에 메일 계정이 저장돼 있어야 보냅니다.
- 기본: **1일 전부터**, 팝업·메일 켜짐, 미리보기 없이 발송.

## 8. 데이터 폴더 구조와 백업

```
[데이터 폴더]/
├─ data/
│  ├─ inspections.json   검수 건 (협의 기록, 결과, 첨부 목록, 변경 이력 포함)
│  ├─ vendors.json       업체
│  ├─ inspectors.json    사내 검수자
│  ├─ settings.json      충돌 조건, 메일 템플릿, 알림, 검수 품목 등 (공통 설정)
│  └─ mail_log.json      메일 발송 기록
├─ 원본/YYYY-MM/          업체가 보낸 엑셀 원본
├─ 첨부/<신청번호>/        첨부파일 (_삭제됨/ 에 삭제한 파일 보관)
├─ 백업/                  저장할 때마다 이전 data/ 자동 백업
└─ .lock                 '편집 중' 표시
```

- **백업**: 저장할 때마다 직전 상태가 `백업/` 에 쌓입니다 (기본 50개, 넘으면 오래된 것부터 삭제).
- **복원**: 설정 → 데이터 폴더 → **백업에서 복원** → 시점 선택. 복원 직전 상태도 백업해 두므로 되돌릴 수 있습니다.
- JSON 파일을 메모장 등으로 **직접 고치지 마세요**. 깨지면 프로그램이 저장을 멈추고 복원을 안내합니다.

## 9. 문제가 생겼을 때

| 증상 | 해결 |
|---|---|
| "데이터 폴더에 접근할 수 없습니다" | 클라우드독이 실행 중인지, 동기화가 연결돼 있는지 확인 → [다시 시도] |
| "○○○이(가) HH:MM에 수정했습니다" | [새로 불러오기] 후 다시 입력 (내 변경은 저장되지 않았음) |
| "다른 PC가 저장하는 중이라…" | 몇 초 뒤 다시 저장 |
| "파일이 손상되어 읽을 수 없습니다" | 동기화가 끝났는지 확인 후 새로 불러오기 → 계속되면 설정 → 백업에서 복원 |
| 엑셀을 넣었는데 "머리글을 찾을 수 없습니다" | 우리 양식이 아닌 파일. 업체에 빈 양식으로 다시 작성 요청 |
| `.xls` 파일 | 엑셀에서 "다른 이름으로 저장 → Excel 통합 문서(.xlsx)" 후 넣기 |
| "메일 계정 또는 비밀번호가 맞지 않습니다" | 설정 → 메일 발송 설정에서 다시 입력. 웹메일에서 SMTP 허용 여부를 IT에 확인 |
| "메일 서버에 연결할 수 없습니다" | 서버 주소·포트·보안 방식 확인, IT에 SMTP 허용 확인. 급하면 수동 방식 사용 |
| 팝업 알림이 안 뜸 | 검수자 관리에서 내 Windows 계정(또는 표시 이름)이 연결돼 있는지, 설정 → 알림의 팝업이 켜져 있는지 |
| 알림 메일이 안 감 | 자동(SMTP) 방식인지, 그날 처음 연 PC에 메일 계정·비밀번호가 저장돼 있는지 (메일 이력에서 확인) |

### 엑셀 양식이 바뀔 때
- 열은 **머리글 이름**으로 찾습니다. 순서가 바뀌어도 됩니다.
- 항목이 바뀌면 `data/settings.json` 의 `excelTemplates` 에 새 버전을 추가하고 `currentTemplate` 을 바꿉니다.
  빈 양식의 숨김 시트(`_meta`)에 양식 버전이 기록되어, 옛 양식 회신도 그 버전 열 정의로 읽습니다.

```json
{ "version": "v2", "sheetName": "검수신청",
  "columns": [ { "key": "id", "header": "신청번호" }, { "key": "vendorName", "header": "업체명", "required": true }, "…" ] }
```

### 데이터 구조 버전
- 모든 JSON 에 `schemaVersion` 이 있고, 구조가 바뀌면 `src/main/core/schema.ts` 의 `MIGRATIONS` 로 자동 변환합니다.
- 저장은 임시 파일에 쓴 뒤 교체(동기화 중 깨짐 방지), `revision` 비교로 덮어쓰기 방지, `data/.writing` 저장 잠금.

src/shared/       상태 흐름, 충돌 검사, 메일 템플릿, 알림 대상 (화면·메인 공용)
