외주업체가 신청한 검수 일정을 등록 → 협의 → 확정/변경/취소 → 검수 → 합격/불합격까지 관리하고 업체에 메일로 알리는 Windows 데스크톱 프로그램(Electron + React + TypeScript)의 UI 기준입니다. 월 검수 10~20건, 거래 업체 10곳 이내를 매일 쓰는 사내 담당자용이므로 화려함보다 한눈에 읽히고 빠르게 처리되는 것을 우선합니다. 화면 문구는 모두 한국어입니다.

## 내용 원칙 (Content fundamentals)
- 버튼은 동사형 짧은 말(`확정`, `변경`, `취소`, `결과 입력`, `메일 보내기`, `엑셀 내보내기`)로 씁니다. 존댓말 '~합니다/~하세요'를 쓰고, 경고는 원인과 해야 할 일을 함께 씁니다. 예: "다른 사용자(홍길동)가 10:32에 수정했습니다. 새로 불러온 뒤 다시 저장하세요."
- 오류 문구는 칸 단위로 구체적으로: "날짜 형식이 올바르지 않습니다", "필수 항목 누락". 이모지·느낌표를 쓰지 않습니다.
- 날짜는 `11-10(화)`, 시간은 `13:30`(24시간), 기한은 `D-Day`·`D-1`, 건수는 `3건`, 신청번호는 `IN-2611-006` 형식입니다.
- 샘플 데이터는 가상 업체(한솔정밀, 대양산업, 우진전장, 서원테크, 미래기전, 청우소재)와 검수자(김민준, 이서연, 박지훈, 최유진)를 씁니다.

## 시각 기준 (Visual foundations)
- 화면 뼈대는 항상 `AppShell`: 왼쪽 세로 메뉴(`sidebar`) + 상단 바(`surface`) + 본문(`bg`). 기준 1440×900, 최소 1280×720. 장식 요소(그라데이션·그림자 남용·일러스트)를 쓰지 않습니다.
- 강조색은 남색 `primary`입니다. 한 화면에서 `.btn-primary`는 가장 중요한 동작 하나에만 씁니다. 나머지 버튼은 `.btn`, 되돌리기 어려운 동작은 `.btn-danger`.
- 상태 색은 달력·목록·상세·대시보드 어디서나 같은 `--st-*` 토큰으로만 칠합니다: 신청접수=회색, 일정협의중=노랑, 확정=파랑, 변경됨=보라, 취소=연한 빨강(취소선), 검수완료-합격=초록, 검수완료-불합격=채운 빨강. 남색 `primary`와 파랑 '확정'은 명도 차이와 점+글자 배지로 구분합니다.
- 경고·충돌·오류는 반드시 아이콘 + 색 + 문구를 함께 씁니다(`Alert`, `.cell-warn`, `.cell-err`). 색만으로 의미를 전달하지 않습니다.
- 글자: `t-body`(14px) 기본, 표 셀은 `t-body-sm`(13px)이며 13px 미만은 쓰지 않습니다. 숫자 열은 오른쪽 정렬·`tabular-nums`. 글꼴은 `Noto Sans KR`(없으면 `Malgun Gothic`); Electron 배포본에는 글꼴 파일을 앱에 포함하세요.
- 텍스트·배경 대비 4.5:1 이상(라이트·다크 모두), 테두리·포커스 링·점은 3:1 이상. 키보드 포커스는 `focus` 색 2px 링입니다.
- 간격은 `space-1`~`space-6`, 모서리는 `radius-md`(버튼·입력) / `radius-lg`(카드·팝업) / `radius-pill`(배지)만 씁니다. 라이트가 기본이고 `[data-theme="dark"]`로 다크를 지원합니다.

## 구성요소와 화면
- 공통 구성요소: `Button`, `StatusBadge`, `DataTable`, `FormFields`, `Dialog`, `Alert`, `AppShell`. 스타일은 모두 `components/bundle.css` 한 파일의 클래스이며 값은 토큰 변수만 씁니다. React로 옮길 때는 같은 이름의 컴포넌트가 이 클래스를 그대로 붙이게 하세요.
- 화면 카드(`화면` 그룹): `ScreenDashboard`(1) `ScreenCalendar`(2) `ScreenList`(3) `ScreenDetail`(4) `ScreenImport`(5) `ScreenMail`(6) `ScreenVendors`(7) `ScreenInspectors`(8) `ScreenSettings`(9). 알림 팝업(10)은 `Dialog` 카드에 있습니다. 모두 같은 구성요소를 재사용하며, 새 화면도 같은 규칙으로 만듭니다.
- 업체에게 가는 메일 화면에는 자동 발송 버튼을 두지 않고 반드시 미리보기를 거친 뒤 [발송]을 누르게 합니다(수동 방식: 받는 사람/제목/본문 [복사] → [웹메일 열기] → [발송 완료로 기록]).

## 아이콘
선 아이콘(24px 격자, 선 두께 2)을 `.ico` 클래스의 CSS 마스크로 씁니다: `home calendar list upload download building user gear mail search warn error info ok chev file clock`. 이모지는 쓰지 않으며 아이콘은 항상 글자와 함께 둡니다. 크기는 16px(기본)·20px(`ico-lg`).
